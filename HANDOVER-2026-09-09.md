## Project purpose

Wyze Monitor is a local multi-camera dashboard for Wyze cameras that provide a working local RTSP/RTSPS stream. It supports Windows Electron monitoring and Raspberry Pi 4/Pi 5 Docker deployments. The installer accepts any number of cameras; four cameras are the primary tested case.

Supported features include HD/main and Eco/substream selection, per-camera reconnect, enlarged focus view, fullscreen, optional browser-side Smooth30, Pi Desktop/application-menu launch, SSH launch, and a friendly local mDNS URL. The application does not use Wyze cloud API credentials, Docker Wyze Bridge, an API subscription, recording, audio, object detection, or a login screen.

## Media architecture

~~~text
Wyze RTSPS/H.264
  -> FFmpeg exec producer (-an -c:v copy)
  -> go2rtc
  -> WebRTC (MSE fallback)
  -> browser H.264 decode
  -> optional WebGL Smooth30 canvas
~~~

FFmpeg remuxes compressed H.264 and does not decode or re-encode video. Each camera creates an `ID_main` stream from `stream0` and an `ID_sub` stream from `stream1`. Producers start on demand.

Smooth30 blends decoded frames on a 30 Hz canvas. `SRC` is the camera-originated rate; `OUT` is the generated presentation rate. `SYNTHETIC 30` is explicitly labelled. It adds roughly one source-frame of latency and may ghost during motion. `OUT 30` is not 30 captured camera frames and must not replace the original stream for recording or evidence.

The MVLS-30 design in `research/30fps` is a proposal, not shipped code and not a worldwide novelty claim.

## Installation

Use a normal Pi login with sudo access:

~~~bash
sudo apt-get update
sudo apt-get install -y git curl
git clone https://github.com/bobster316/go2rtc-wyze-monitor.git
cd go2rtc-wyze-monitor
chmod +x raspberry-pi/*.sh raspberry-pi/wyze-monitor
./raspberry-pi/install.sh --dry-run
./raspberry-pi/install.sh
~~~

The installer detects Pi model and userland architecture, checks OS/memory/storage/Docker/ports, offers Docker from the signed Debian repository, runs the repeatable camera wizard, writes mode-600 private files, installs Avahi and launchers, builds the isolated Compose project, and starts only go2rtc and monitor-web.

The wizard asks for display name, reserved IPv4, RTSP username and password per camera. Passwords are hidden. After camera changes, setup force-recreates monitor services so the mounted configuration reloads.

Open `http://wyze-monitor.local`, or the numeric diagnostic address. Lite uses a browser on another device. SSH commands are:

~~~bash
wyze-monitor
wyze-monitor status
wyze-monitor restart
wyze-monitor stop
wyze-monitor logs
wyze-monitor configure
wyze-monitor url
~~~

## Configuration and privacy

Public examples are `cameras.example.yaml` and `raspberry-pi/.env.example`. Private ignored files are `cameras.yaml`, `raspberry-pi/.env`, `raspberry-pi/runtime/go2rtc.yaml`, and Windows `go2rtc/go2rtc.yaml`.

Each camera needs a reserved address, RTSP username and RTSP password. These are per-camera RTSP credentials, not the Wyze account password. Do not place a full credential-bearing RTSP URL in the repository.

The public source, release ZIP and Git history were scanned for credentials. Private footage, API keys, SSH keys, browser profiles, generated runtime YAML, personal home paths and account names are excluded. Private LAN IPs are retained in this handover by request.

## Friendly URL and first-request troubleshooting

The friendly URL is published by Avahi and is intended for the same LAN. Only one host may own a given name. Docker bindings and WebRTC ICE candidates use `PI_HOST_IP` from `raspberry-pi/.env`, so reserve the Pi address.

The first Windows request to the friendly URL took about 2.8 seconds in one check, while the numeric address took about 39 ms; later requests took roughly 23–47 ms. The refused-connection event was not reproduced. Use the numeric URL first, ensure the browser uses `http://` rather than `https://`, check same-LAN mDNS, and update `PI_HOST_IP` if the address changed. The available SSH key was rejected during follow-up inspection, so systemd restart counters were not retrieved.

## Windows setup

Install Node.js 22 LTS, Git and FFmpeg. Run `scripts/setup.ps1` twice: first it creates `cameras.yaml` and exits; after editing with your camera settings, rerun setup and use `npm start`. The Windows dashboard is `http://127.0.0.1:8765`. Setup pins go2rtc v1.9.14 and uses `npm ci`.

## Backup, recreation and removal

Back up `cameras.yaml` and `raspberry-pi/.env` privately. Generated runtime YAML and `node_modules` can be recreated. For a Pi backup:

~~~bash
umask 077
tar -czf ../wyze-monitor-private-backup.tar.gz cameras.yaml raspberry-pi/.env
chmod 600 ../wyze-monitor-private-backup.tar.gz
~~~

For a new Pi, install the same or a reviewed newer release, copy `cameras.yaml`, let `install.sh` create a fresh `.env`, and verify every camera. If the Pi address changes, edit `PI_HOST_IP`, rerun install, restart `wyze-monitor-url`, and check status. See `docs/OPERATIONS.md` for scoped removal commands. Do not Docker-prune or uninstall Docker/Avahi when other applications use them.
